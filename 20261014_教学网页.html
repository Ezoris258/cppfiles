① 哈希表 Hash Table

哈希表，就是「把东西放进带号码的柜子，找的时候直接去那个柜子拿」。

🧺 先听一个生活故事

学校门口的储物柜

学校门口有 10 个储物柜，柜子上写着号码：0、1、2、3 … 9。

你帮全班同学存东西。每个同学都有一个学号（比如 23 号、33 号、45 号……）。

你的规则是：学号 ÷ 10，余数是几，就放进几号柜。

例
23 ÷ 10 余 3 → 放进 3 号柜。
例
45 ÷ 10 余 5 → 放进 5 号柜。

想找 23 号同学的东西时，不用一个柜子一个柜子翻，直接去 3 号柜，一下就找到了！

🔑 三个重要的词

1
键（Key）：就是「学号」。它是东西的名字号码。
2
哈希函数：就是那个「÷10 看余数」的规则。它把一个大数字，变成一个小的柜子号。
3
冲突：两个不同的学号，算出了同一个柜子。
💥 什么是冲突？
23 ÷ 10 余 3，33 ÷ 10 也余 3。两个人都想去 3 号柜，这就是「冲突」。
怎么办？—— 在 3 号柜里挂一串，像钥匙串一样，一个连着一个。这个方法叫「拉链法」。

⚡ 为什么它很快？

如果没有哈希表，要找一个东西，可能要从头一个一个看（很慢）。

有了哈希表，算出柜子号，一步就走到那个柜子。我们把这种「不用一个个找」的速度，写成 O(1)。

💻 代码长这样（先看个大概，下面一行行讲）

const int MOD = 100003;   // 柜子总数（用质数，冲突更少）
int head[MOD], nxt[N], key[N], val[N], tot;

void insert(int k, int v) {        // 存入：名字号码 k，值 v
    int h = (k % MOD + MOD) % MOD; // 算柜子号 h（负数也安全）
    key[++tot] = k;                // 记下这个名字号码
    val[tot] = v;                  // 记下它的值
    nxt[tot] = head[h];            // 新东西连到柜子原来的第一件
    head[h] = tot;                 // 柜子现在指向新东西
}

int find(int k) {                  // 查找：名字号码 k
    int h = (k % MOD + MOD) % MOD; // 先算柜子号
    for (int i = head[h]; i; i = nxt[i]) { // 顺着那串一件件看
        if (key[i] == k) return val[i];    // 找到了！把值还给你
    }
    return -1;                     // 找遍了都没有
}

👆 现在可能有点晕，没关系，我们一行一行看。

🔍 一行一行看代码

int head[MOD], nxt[N], key[N], val[N], tot;

准备了 4 个本子 + 1 个计数器：
• head[h] = 「h 号柜里第一件东西」放在哪。
• key[] = 每件东西的名字号码。
• val[] = 每件东西的值。
• nxt[] = 同一柜里「下一件」在哪（像钥匙串，一个连一个）。
• tot = 已经存了几件东西。

int h = (k % MOD + MOD) % MOD;

这就是「哈希函数」！ k % MOD 就是「k ÷ MOD 看余数」。
外面多包一层，是为了让负数也能算出正确的柜子号。

nxt[tot] = head[h]; head[h] = tot;

像往链子最前面挂一个新钥匙：新东西先连上柜子原来的第一件，然后让柜子指向这个新东西。

for (int i = head[h]; i; i = nxt[i])

查找时顺着链走：从柜子的第一件开始，一件一件看下一件，直到看完。

return -1; // 未查找到目标

没找到就给一个特殊数字 -1，表示「这里没有」。

② 线段树 Segment Tree

线段树，就是「提前把队伍分好小组、记好每组的总数，问的时候不用从头数」。

🏫 再听一个生活故事

体育老师查身高

班上有 8 个同学站成一排。老师经常问：「第 3 个到第 6 个同学的身高加起来是多少？」

如果每次从头一个一个加，问得多了就很慢。

聪明的办法：提前把队伍分成小组，每个小组选一个小组长，组长记住「我们这组身高总和」。

小组再合成大组，大组的组长也记住总和。这样从上到下，像一棵倒过来的树。

老师要问第 3～6 个，只需要找到几个合适的小组，把它们的总和加一下就出来了——很快！

🌳 线段树长什么样？

把一排数字一直对半切：

一整排 8 个 → 切成 4 个 + 4 个 → 再切成 2 + 2 + 2 + 2 → 最后每个都是 1 个。

每个「一段」都有一个组长，记着这一段的总和。

因为每次都切成两半，所以层数很少（大约 log₂n 层），所以很快，写作 O(log n)。

📝 什么是「懒标记（Lazy Tag）」？

📌 一个贴便签的故事：
老师想让「第 3 到第 6 个同学每人 +5 厘米」。
不用真的一个个去改！只需在小组长那里贴一张便签：「这组每人 +5」。
等以后真的需要问这组每个人的具体身高时，组长才把便签发下去。
这张「先记着、以后再做」的便签，就叫懒标记。

懒标记有两句话要记住：

1
组长自己的数字是最新的、正确的（比如总和已经加了 5×人数）。
2
组员（孩子）的数字还是旧的，等需要时再把便签发下去更新。

💻 核心代码（看个大概）

void apply(int p, int l, int r, long long k) {
    sum[p] += (r - l + 1) * k;   // 这段有 (r-l+1) 个元素，每个 +k
    lazy[p] += k;                 // 贴便签：这段欠下的修改
}

void pushdown(int p, int l, int r) {
    if (lazy[p] == 0 || l == r) return;  // 没有便签，或已是最小的段
    int mid = (l + r) / 2;
    apply(p << 1, l, mid, lazy[p]);       // 便签发给左孩子
    apply(p << 1 | 1, mid + 1, r, lazy[p]); // 便签发给右孩子
    lazy[p] = 0;                     // 便签发完了，清空
}

void update(int p, int l, int r, int ql, int qr, long long k) {
    if (ql <= l && r <= qr) { apply(p, l, r, k); return; } // 整段都要改
    pushdown(p, l, r);                 // 先发掉旧的便签
    int mid = (l + r) / 2;
    if (ql <= mid) update(p << 1, l, mid, ql, qr, k);
    if (qr > mid) update(p << 1 | 1, mid + 1, r, ql, qr, k);
    sum[p] = sum[p << 1] + sum[p << 1 | 1];   // 重新算组长的总和
}

👆 别慌，下面挑最重要的两处讲。

🔍 挑两处最重要的讲

sum[p] += (r - l + 1) * k;

这段队伍有 (r-l+1) 个人，每个人 +k，所以总和就要加 (r-l+1)×k。

pushdown —— 把便签发下去

当我们需要查看更细的小组时，组长要把便签先发给左、右两个孩子，然后把自己的便签清空。这样孩子的最新数字就对了。

🧮 例题一：A − B 数对（用哈希表）

题目在问什么？

给你一串数字，还有一个数字 C。问你：有多少对数字 (A, B)，能让 A − B = C？

比如数字是 [3, 5, 8]，C = 3：
• 8 − 5 = 3 ✔️
• 5 − 3 = 2 ✖️（不是 3）
所以答案是 1 对。

1
换个说法： A − B = C，也就是 B = A − C。所以对每个 A，只要知道「A − C」出现了几次就行。
2
用哈希表数次数：先读一遍数字，用哈希表记下「每个数字出现了几次」。
3
再查一遍：对每个 A，去哈希表里查「A − C」出现几次，加起来就是答案。
unordered_map<long long, long long> cnt;   // 哈希表：数字 → 出现次数
for (int i = 0; i < n; i++) { cin >> a[i]; cnt[a[i]]++; }  // 数次数
long long ans = 0;
for (int i = 0; i < n; i++) {
    auto it = cnt.find(a[i] - c);        // 找 A-C
    if (it != cnt.end()) ans += it->second; // 找到就加上次数
}
cout << ans << "\n";
⚠️ 小心：答案可能很大，用 long long 存，别用 int，不然会「装不下」（溢出）。

📏 例题二：线段树 1（用线段树）

题目在问什么？

给你一排数字，有两种操作：

• 操作 1：把第 x 到第 y 个数字，每个都 +k。

• 操作 2：问第 x 到第 y 个数字的总和。

1
用线段树存「每段的总和」，这样查总和很快。
2
要「一段都 +k」时，用懒标记，不用一个个改。
3
要问具体总和时，先把懒标记发下去（pushdown），再算。
⚠️ 两个坑：
1. 发完便签后，记得清空组长自己的便签（lazy[p] = 0）。
2. 总和可能非常大（到 2×10¹⁸），要用 long long。

④ 总结 + 总测验 回顾

📋 今天记住这两张「小卡片」就够了

🧺 哈希表 = 储物柜
• 用一个规则（哈希函数）算出「放哪个柜子」。
• 两个东西挤一个柜子 = 冲突，用「拉链法」串起来。
• 找东西一步就到，速度 O(1)。
🌳 线段树 = 分组小组长
• 把一排数字一直对半切，做成树。
• 每段有个组长，记着这段的总和。
• 懒标记 = 「先记着、以后再做」的便签。
• 查和改都很快，速度 O(log n)。

🎯 总测验（最后考考你）

想要「一步就找到」一个数字出现了几次，用哪个？
想要「快速查一段的总和、还能一段都 +k」，用哪个？
答案可能很大时，要用什么类型存，防止「装不下」？
